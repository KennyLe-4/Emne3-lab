Lab-kommandoer

Klikk «Kopier» på hver blokk. Bytt ut <victim-ip> og <KALI-IP> med dine egne adresser.

Victim står på Host-Only hele tiden, aldri internett. Bare Kali har internett (NAT). Du jobber mot victim fra Kali via SSH: labadmin / labadmin2026.

Steg 1: Logg inn på victim og finn IP

Logg inn på victim-konsollen (labadmin / labadmin2026) og finn IP-en. Skriv den ned, du trenger den fra Kali.

hostname -I

Steg 2: Finn victim fra Kali og SSH inn

På Kali: finn victim på host-only-nettet, og logg inn over SSH. Bytt .x og <victim-ip> med dine egne verdier.

ip -4 addr | grep 192.168
sudo netdiscover -r 192.168.x.0/24
ping <victim-ip>
ssh labadmin@<victim-ip>

Steg 3: Oppsett av Suricata (på victim, via SSH)

Kjør de tre blokkene i rekkefølge. Vent til hver er ferdig før du går videre.

Blokk 1 — finn og sett riktig nettverkskort (host-only-kortet, det uten internett-rute)
ip -br a
# host-only-kortet er det som IKKE har internett-ruten (default gateway)
GW=$(ip route show default 2>/dev/null | awk '{print $5; exit}')
IFACE=$(ip -br -4 addr | awk -v gw="$GW" '$1!=gw && $1!~/^(lo|docker|br-|veth|virbr)/ && $3 ~ /^192\.168\./ {print $1; exit}')
[ -z "$IFACE" ] && IFACE=$(ip -br -4 addr | awk '$1!~/^(lo|docker|br-|veth|virbr)/ && $3 ~ /^192\.168\./ {print $1; exit}')
echo "Suricata skal lytte paa: $IFACE"
sudo sed -i "0,/- interface:.*/ s//- interface: $IFACE/" /etc/suricata/suricata.yaml
Blokk 2 — reparer lab-regelen (SID 1000005)
sudo sed -i '/sid:1000005/d' /var/lib/suricata/rules/local.rules
printf '%s\n' 'alert http any any -> $HOME_NET any (msg:"LAB command-injection"; flow:to_server; http.uri; content:"ping.php"; content:"host="; pcre:"/host=[^&]*[\x3b&|\x60]/U"; classtype:web-application-attack; sid:1000005; rev:2;)' | sudo tee -a /var/lib/suricata/rules/local.rules >/dev/null
Blokk 3 — start Suricata og sjekk at den kjører (skal svare "active")
sudo systemctl restart suricata && sleep 5 && systemctl is-active suricata

Steg 4: Wazuh SOC på Kali

På Kali (Kali skal ha både NAT og Host-Only på). Henter og starter SOC-en. Når den er ferdig, skriver den ut dashboard-login og connect-linja til victim. Ta vare på den.

cd ~
curl -O https://nocryptoshade.github.io/e3/setup-soc-wazuh.sh
ls -l setup-soc-wazuh.sh
sudo bash setup-soc-wazuh.sh

Hvis Docker-installasjonen feiler (gammel Kali), kjør dette først og deretter scriptet på nytt:

sudo apt update
sudo apt full-upgrade -y
sudo reboot

Steg 5: Koble agenten (på victim)

På victim: pek agenten mot Kali sin Host-Only-IP og start den. Bytt <KALI-IP> med adressen scriptet skrev ut. I dashboardet under Agents skal victim vise "Active" innen et minutt.

sudo sed -i 's|<address>.*</address>|<address><KALI-IP></address>|' /var/ossec/etc/ossec.conf
sudo systemctl enable --now wazuh-agent

Steg 6: Send Suricata-alarmene inn i Wazuh (på victim)

På victim: la Wazuh-agenten lese Suricata sin eve.json, så nettverksalarmene havner i samme dashboard. Kopier hele blokka samlet.

sudo python3 - <<'PY'
from pathlib import Path
p = Path("/var/ossec/etc/ossec.conf")
s = p.read_text()
entry = """  <localfile>
    <log_format>json</log_format>
    <location>/var/log/suricata/eve.json</location>
  </localfile>
"""
if "/var/log/suricata/eve.json" not in s:
    s = s.replace("</ossec_config>", entry + "\n</ossec_config>")
    p.write_text(s)
    print("Suricata log collection added.")
else:
    print("Suricata log collection is already configured.")
PY
sudo systemctl restart wazuh-agent

Steg 7: Verifiser (på Kali)

På Kali: kjør noen triggere, og sjekk i dashboardet. Dashboard → Threat Hunting: filtrer på rule.groups: authentication_failed for host-hendelser, og rule.groups:suricata for nettverksalarmer.

VICTIM=192.168.x.x
curl -s -o /dev/null "http://$VICTIM/portal/ping.php?host=127.0.0.1;id"
hydra -l baduser -p wrongpass -t1 ssh://$VICTIM
